# Editable local creation and revision

Use for arrangements, procedural effects, and no-spend creation. Read `local_catalog`
and current schemas. Choose an explicit project/session and save the brief, section
purposes, roles, and intended listening effect. User briefs supply style; the skill
does not supply fixed genre profiles. Start with a short preview, then develop it.

For “change the instruments but keep the tune,” read the affected tracks and
patterns, change instrument/mix fields only, and save with the expected revision.
Render both versions and check the theme data stayed unchanged. Clone a pattern
before changing only one occurrence; shared-pattern edits affect all references.
Restore creates new history rather than erasing old revisions. Resolve conflicts
by reading and reconciling, never overwriting a concurrent edit.

Keep request IDs for render recovery. Poll `arrangement_job`; inspect outputs and
errors before resubmitting. Local failure does not authorize paid fallback. Save
initial and revised assets in a compact review explaining what changed and why.
Use at most three creative revision rounds for a trial; tool defects still require
implementation fixes. Agents may open reviews but cannot start audio. Technical
measurements, model audio observations, and human acceptance are distinct evidence.

If output is silent inspect clips, source availability, gain, mute/solo, and
register before rewriting the composition. If revision changed too much, restore
the prior version and apply a smaller edit. A simple one-shot may not need a large
arrangement. Preserve the simplest useful editable recipe.

Export mixes, aligned stems/components, and a package when needed. Preserve exact
revisions, engine versions, seeds, source hashes, and lineage. Missing dependencies
must fail visibly. Derive arrangements from MIDI without rewriting original assets.
These are operational constraints and workflow choices, not promises of quality.
Source: SfxChat shared operation contracts.
